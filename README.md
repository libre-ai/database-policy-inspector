# Libre AI Database Policy Inspector

## Intended use

Help a developer inspect database-related changes and understand findings before deciding what to change. DB Inspector is intended to provide evidence about SQL, access rules and migrations, not to become the durable authority for a product’s data.

## Existing candidates and limits

Earlier sources contain a static command-line inspection candidate for PostgreSQL-related files and rules. This documentary candidate admits no installed CLI, live database connection, automatic repair or guarantee that an application’s access controls are correct.

## Proposed boundaries

A selected inspection states its input files, supported syntax, rule version and limitations. Findings must distinguish observed evidence from unsupported or unavailable analysis. Static inspection is separate from runtime database behavior. Any future live inspection or write capability requires its own explicit scope, permissions and qualification.

## Activation criteria

Qualify selected static rules with representative files, deterministic findings and explicit refusal or unsupported cases. Verify useful output in a clean CLI consumer and absence of unintended writes or disclosure. Static module admission does not require live database integration; a live integration would need separate evidence and does not block documentary repository existence.
